## Built

### Systems
- **Medals and records** (GDD: Medals):
  - Bronze = cleared. Silver = at or under reflect par. Gold = at or under par with zero deaths since entering the room.
  - Medals only go up. An under-par clear is marked ★.
  - Per-room records hold best reflects, best time, deaths and hints used.
- **Save schema v1** (GDD shape, keyed by room id), on the Web Shell's `SaveManager`:
  - versioned envelope, integrity checksum, staged writes, last-known-good backup, recovery on load;
  - a migration table with a v0 → v1 stub;
  - additive fields fall back to defaults. The settings gained `reducedFlashing` and `telemetry`.
- **Assists** (Pause → Assists): game speed 100/75/50%, reflect window Normal/Wide/Very wide, reflect preview, invincibility.
  - Game speed stretches real time per sim step; the sim stays at a fixed 120 Hz.
  - Visual options live in Settings: high contrast, reduced flashing, screen shake.
  - Assists never touch medals.
- **Stuck-player system:**
  - After 10 deaths or 3 minutes in a room, an eye glyph appears in the HUD. H or Pause → Hint restarts the room with a translucent ghost of the designer solution, which stops shortly after its first reflect.
  - After a clear, Results offers *Watch solution*.
  - Hints are recorded in the save and don't affect medals.
- **Opt-in local telemetry** (Settings → Share playtest data):
  - Per room: attempts, deaths, time to first clear, hints, quits.
  - Nothing leaves the device; *Export playtest data* downloads JSON for a tester to send back.
- **Solver** (`test/solver.mjs`), ported from Living Loop's decision-window search:
  - Moves: L / none / R × jump. Reflects use five aims held through contact, pressed on contact, so the bot never whiffs.
  - States are pruned by emitter phase, bucketed player, projectiles and objects. There's a state cap.
  - Two modes: `any` (A* with a progress bonus) and `min` (exhaustive by reflects).
  - Results are cached by content hash in `test/.solve-cache.json` (Living Loop's pattern).
  - Authoring CLIs: `tools/solve.mjs` (records a solution and par) and `tools/trace.mjs` (shows how a room was solved).
- **Comfort diagnostic:** each room re-solved at 4 Hz and 3 Hz decision rates.

### Web Shell integration (pulled forward from M2 where M1 needed it)
- Vendored a fresh build of Web-Game-Shell-v1.02 (`vendor/web-shell/`, source commit noted there).
- In use:
  - `DOMGameUI` for all screens, with keyboard/gamepad/pointer focus navigation;
  - `InputManager` + `BrowserInputSource` for UI input;
  - `InputFamilyDetector`;

- Flow:

## Tested, and how

`npm test` passes at the code commit: 132 headless checks plus about 50 in-browser checks.

**Room checks**
- Schema for all 24 rooms.
- Index and ideas catalogue consistency, no repeated idea, pass-room quota.
- Determinism: solutions replay twice in Node to identical hashes, and Chromium replays match Node bit for bit.
- Each recorded solution clears within par, both headless and through the live game session.

**Solver gates**
- **Solvability:** all 24 rooms are solved within par by the solver. 23 at 5 Hz; c1-09 at 4 Hz, after its 5 Hz search capped.
- **Under-par search (diagnostic):**
  - Every par-1 room exhausted the 0-reflect search, which proves no reflect-free bypass at 5 Hz.
  - c1-09 and c1-20 (par 2) capped at the 1-reflect budget, so they're unproven.
- **Comfort:** every room still solves at 4 Hz and 3 Hz.

**Unit rules**
- All M0 rules plus spikes, walls, and the game-speed timing.

**Browser smoke (Chromium via Playwright)**
- Boot to title; first-boot Prologue; intro skip; run, jump and reflect; R reset; Esc pause and resume; 60 fps in a room.
- Results after a clear, and the medal saved.
- Watch solution and back; assists toggles saved; 75% speed gives about 90 sim steps per second.
- Hint ghost after 10 deaths.
- Save survives a reload; returning players land on the chapter list.
- Editor boots and plays.
- Zero console errors.

**Deploy:** the Vercel production deployment of `9ea2b3d` built and serves the page (status 200, checked through the Vercel connector).

## Not tested

- **The kill criteria.** They need humans: Mike plus 3 outside playtesters. Nothing here measures whether let-it-pass rooms *feel* clever.
- **The live site in a browser.** This sandbox's network policy blocks `*.vercel.app`, so the in-browser checks ran against a local build of the same commit instead.
- Gamepad, touch and haptics on real devices.
- How the audio sounds.
- Migration from a real v0 save. No v0 save ever shipped, so the stub is only exercised by `SaveManager`'s own tests in the shell repo.
- Telemetry export, which triggers a browser file download that the smoke test doesn't capture.
- Whether a human can execute each recorded solution. They're bot runs with contact-timed reflects. The comfort runs say the decisions are coarse, but the hint ghost replays that bot run, not a human one.

## Known issues and decisions

- The solver needs 4 Hz for c1-09 and caps at par − 1 for the two par-2 rooms. When sim code changes, the cache is dropped and an uncached `npm test` takes roughly 30–60 minutes. CI will pay that once per sim change.
- Room select is a list, not the node-grid map. The map, mirror flip and Examiner nodes are M2.
- W/Up still don't jump (the M0 deviation stands).
- The Web Shell's own repo has a stale committed `dist/`. It's worth rebuilding there.
- There is no `main` branch yet. The repo's only branch is this one, which is also what Vercel deploys to production.

None. New presentation-only knobs live in their modules: intro 0.8 s, hint thresholds (10 deaths / 3 min) and hint tail 0.6 s in `src/game/session.js`.
